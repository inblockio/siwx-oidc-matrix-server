# siwx-oidc-matrix-server

Docker Compose deployment stack that runs a Synapse Matrix homeserver fronted by
siwx-oidc (CAIP-122 OIDC provider) so agents and wallets can authenticate with
EIP-191, Ed25519, or P-256 keys.

## Repository structure

```
siwx-oidc-matrix-server/
  start-matrix.sh          # CLI entry point — parses args, writes .env (chmod 600), calls docker compose up
  docker-compose.yml       # Production stack (Synapse + siwx-oidc + nginx-proxy + acme-companion + Redis)
  deploy.sh                # Deploys to agentic.inblock.io (SCP files + Caddy config + siwx-oidc clone)
  dockerfiles/
    Dockerfile             # FROM matrixdotorg/synapse:v1.152.1; installs yq; COPYs entrypoints/matrix_server.sh
    Dockerfile.element     # FROM vectorim/element-web:v1.12.18; COPYs config + favicon branding
  entrypoints/
    matrix_server.sh       # Container entrypoint — first-boot: generates homeserver.yaml via yq
    element_entrypoint.sh  # Container entrypoint — templates env vars into config.json, replaces favicons
  config/
    element-config.json    # Element Web config with m.authentication OIDC discovery
    inblockio_logo_dark.png # inblock.io branding
    favicon-*.png, favicon.ico  # inblock.io favicon set (replaces Element's vector-icons)
  .env                     # Generated by start-matrix.sh; chmod 600; not committed
  .env.example             # Reference / minimal example
```

## Services

| Service          | Image / Build                              | Port(s)       | Notes |
|------------------|--------------------------------------------|---------------|-------|
| `matrix_synapse` | `matrixdotorg/synapse:v1.152.1` (via Dockerfile) | 8448 | Depends on `siwx-oidc` healthcheck |
| `siwx-oidc`      | Built from `../siwx-oidc` (local)          | `SIWEOIDC_PORT` (default 8081) | CAIP-122 OIDC provider + MSC3861 token introspection |
| `redis`          | `redis`                                    | internal      | Session/token/device store for siwx-oidc (AOF persistence) |
| `proxy`          | `nginxproxy/nginx-proxy:alpine`            | 80, 443       | Reverse proxy; aliases both hostnames on the Docker network |
| `letsencrypt`    | `nginxproxy/acme-companion`                | ---            | Auto-provisions TLS for proxy |
| `element-web`    | `vectorim/element-web:v1.12.18` (via Dockerfile.element) | 80 (internal) | Native MSC3861 OIDC client at `${CLIENT_HOST}` |

Volumes: `matrix_data` (Synapse data), `proxy_data_*` (nginx/acme state).

## First-boot vs. restart behaviour

`entrypoints/matrix_server.sh` only runs the `yq` configuration block when
`/data/homeserver.yaml` does not yet exist. **After first boot, changes to that
script do NOT propagate to running deployments.** To apply changes on an existing
deployment you must also edit `/data/homeserver.yaml` directly inside the
`matrix_data` volume.

## Key configuration facts

- **Synapse auth**: Uses stable `matrix_authentication_service` config (Synapse >= 1.136).
  Synapse discovers OIDC metadata via `{endpoint}/.well-known/openid-configuration`
  on the internal Docker network. A single `secret` covers both introspection auth
  and MAS provisioning.
- **OIDC discovery**: Element discovers the OIDC provider via `m.authentication` in
  both `element-config.json` and `.well-known/matrix/client` (served by Caddy).
- **OIDC issuer env var**: `SIWEOIDC_BASE_URL` (env prefix kept as `SIWEOIDC_`
  for backward compat even though the crate is now `siwx_oidc`).
- **Localpart derivation**: siwx-oidc converts `did:pkh:eip155:1:0xABC...` to
  `did-pkh-eip155-1-0xabc...` (colons to dashes, lowercased).
- **Signing key**: EC P-256 PEM stored as `SIWEOIDC_SIGNING_KEY_PEM` in `.env`
  (chmod 600, gitignored). Generated once by `start-matrix.sh`; passed to the container
  via environment variable. Do not delete from `.env`, tokens become invalid if the
  key changes.
- **Compat layer**: Caddy routes `/_matrix/client/v3/{login,logout,refresh}` to
  siwx-oidc (Synapse disables these under MSC3861). Standard OIDC clients use the
  token endpoint directly; the compat layer serves legacy Matrix clients.

## Admin promotion

Two mechanisms are provided:

### `/set-admin` skill (manual, one-shot)
```bash
/set-admin did:pkh:eip155:1:0xYourAddress
```
Reads `MATRIX_HOST` from `.env`, derives the Matrix localpart, and promotes via SQLite.
The user must have logged in at least once. No restart required.

### `MATRIX_ADMIN_DID` env var (automatic, every boot)
Set in `.env` or pass to `start-matrix.sh`. The entrypoint runs an idempotent promotion
on every container start. Silently defers if the user hasn't logged in yet.

**Security note for both mechanisms**: values are passed to Python via environment variables
and read with `os.environ` — never interpolated into Python source code. Input is validated
against `^did:[a-z]+:[a-z0-9]+:[a-z0-9]+:0x[0-9a-fA-F]{40}$` before use.

## Element Web client

A self-hosted Element Web instance (v1.12.18) is included in the stack, accessible
at `https://${CLIENT_HOST}`. Element discovers the OIDC provider via
`m.authentication` in its config and handles the full MSC3861 OIDC flow natively:
login, token refresh, device management, and logout.

No Element Web fork is needed. The stock `vectorim/element-web` image is used as
a base with inblock.io favicon branding applied at container start. To update
Element, change the tag in `dockerfiles/Dockerfile.element`.

## Common operations

```bash
# First-time start (production)
./start-matrix.sh \
  --MATRIX_HOST matrix.example.com \
  --SIWEOIDC_HOST siwx-oidc.example.com \
  --CLIENT_HOST element.example.com \
  --LETSENCRYPT_EMAIL you@example.com

# Stop
./start-matrix.sh --stop

# Destroy all data (irreversible)
./start-matrix.sh --reset

# Debug mode (foreground, verbose logs)
./start-matrix.sh --ENABLE_DEBUG \
  --MATRIX_HOST matrix.example.com \
  --SIWEOIDC_HOST siwx-oidc.example.com \
  --LETSENCRYPT_EMAIL you@example.com

# Rebuild Synapse image after entrypoint changes
docker compose build matrix_synapse

# Apply a homeserver.yaml fix to a live deployment
docker compose exec matrix_synapse \
  yq -i '.matrix_authentication_service.secret = "NEW_SECRET"' /data/homeserver.yaml
docker compose restart matrix_synapse
```

## Migrating existing deployments from experimental to stable config

If `homeserver.yaml` was generated by an older entrypoint using `experimental_features.msc3861`:

```bash
docker compose exec matrix_synapse sh -c '
  yq -i "del(.experimental_features.msc3861)" /data/homeserver.yaml &&
  yq -i ".matrix_authentication_service.enabled = true" /data/homeserver.yaml &&
  yq -i ".matrix_authentication_service.endpoint = \"http://siwx-oidc:8081\"" /data/homeserver.yaml &&
  yq -i ".matrix_authentication_service.secret = \"${MAS_SHARED_SECRET}\"" /data/homeserver.yaml &&
  yq -i ".matrix_authentication_service.account_management_url = \"${SIWEOIDC_BASE_URL}\"" /data/homeserver.yaml
'
docker compose restart matrix_synapse
```

## MSC3861 Delegated Auth

The stack uses MSC3861 delegated authentication (stable `matrix_authentication_service` config):

- Synapse delegates ALL auth to siwx-oidc via token introspection (`POST /oauth2/introspect`)
- Opaque tokens: `mat_` (access, 300s TTL), `mcr_` (refresh, 86400s TTL)
- Token refresh: via `/token` endpoint with `grant_type=refresh_token` (standard OAuth2)
- User provisioning: siwx-oidc calls `/_synapse/mas/` endpoints to create users/devices
- Device lifecycle: `SIWX_` prefixed device IDs, persistent in Redis across sessions
- Cross-signing reset: only on first login for a new device (not every login)
- Compat layer: siwx-oidc handles `/_matrix/client/v3/{login,logout,refresh}` for legacy clients

Key env vars:
- `MAS_SHARED_SECRET`: Shared between Synapse and siwx-oidc for introspection auth
- `SIWEOIDC_MAS_SHARED_SECRET`: Same value, consumed by siwx-oidc (figment prefix)
- `SIWEOIDC_SYNAPSE_ENDPOINT`: How siwx-oidc reaches Synapse (e.g., `http://matrix_synapse:8080`)

## Security posture

**Core assumption**: SSH (key-only) is the outer boundary. The shell/Docker exec surface
is the inner surface and is treated as trusted.

| Area | Status | Notes |
|---|---|---|
| `.env` permissions | `chmod 600` set by `start-matrix.sh` | Protects secrets from other local users |
| OIDC signing key | In `.env` only, not on disk as a file | Env var passed to container; no TOML mount |
| siwx-oidc port | Internal Docker network only | Not bound to host interface |
| TLS certs in Synapse | `:ro` mount | No write access from container |
| Synapse secrets in volume | Inside `matrix_data` Docker volume | Accessible only via host shell/exec |
| Docker socket (proxy/acme) | Required by nginx-proxy pattern | Known trade-off; exec on those containers = root |
| Federation port 8448 | Publicly exposed, by design | Required for Matrix federation |
| SQLite | In use | Adequate for small deployments; PostgreSQL needed for scale |

**Host firewall note**: Docker manages iptables directly and bypasses UFW rules for
published ports. To restrict access using UFW, add rules to the `DOCKER-USER` chain:
```bash
# Allow federation port only (example — adjust CIDRs as needed)
ufw route allow in on eth0 to any port 8448
# Or use iptables DOCKER-USER chain directly for finer control
```
